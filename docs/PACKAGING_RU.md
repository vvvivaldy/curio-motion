# Повторяемая поставка Curio Motion

Это маршрут maintainer для исходного проекта. Нужен Node из объявленной среды; упаковка/проверка не требуют установленных npm-зависимостей, Python, глобального архиватора, аккаунта или сети. Git нужен только для commit/history режимов. Команды ничего не публикуют и не создают тег.

## Состав и отдельный кандидат

[Политика](../release/payload-policy.json) перечисляет корневые файлы, каталоги и обязательные элементы. Публикуются исходники/инструкции, принятые фильмы, публичные материалы и их notices. Исключаются `.git`, зависимости, caches, `dist`, `qa`, `outputs`, `.env*`, служебные файлы и объявленные `local-only` whole inputs. Пакет не переписывает источник: замены внутри него допускаются только для генерируемых `MANIFEST.sha256` и `PACKAGE_SOURCE.json`.

Изменённый checkout упаковывается только явно как working snapshot:

```sh
npm run test:release
npm run manifest:update
npm run verify:package
npm run package:source -- --working-tree --candidate local-check --out outputs/packages/final-a
```

В папке появятся ZIP, `.zip.sha256` и `.zip.receipt.json`. Имя содержит текущую package-версию и отдельный candidate label: это не замена опубликованного релиза с той же версией. Существующий файл не перезаписывается. Если прерванная команда оставила неполный файл, не считайте его замороженным: проверьте результат и сохраните его отдельно перед новой попыткой.

Пакер проверяет nested SHA/текущие metadata, а не «исправляет» их под любые изменённые bytes. Он читает источник повторно до записи и отказывает при изменении выбранных файлов. Output выбирайте вне публикуемых каталогов (`outputs/packages` либо внешняя папка). Символьные ссылки в выбранном дереве и его предках отвергаются; внешняя ссылка не превращается в файл архива. У source tree не должно быть враждебных одновременных изменений другими процессами: обычная проверка пути/повторный snapshot не является OS-песочницей.

## Точная проверка

```sh
# HASH — сохранённый ожидаемый SHA256 из независимого доверенного источника:
npm run verify:release -- --archive /path/candidate.zip --sha256 HASH
# Дополнительно — байты того рабочего checkout, из которого строили:
npm run verify:release -- --archive /path/candidate.zip --working-tree --sha256 HASH
```

Проверяется структура ZIP/CRC, безопасные уникальные пути, единственный корень, полное соответствие root manifest, все найденные nested `SHA256SUMS.txt`/`MANIFEST.sha256`, текущие SFX file/hash связи и ограниченный credential scan. Source comparison сравнивает все негерируемые файлы, включая имена и отсутствие лишних/пропавших элементов. Исключения не задаются произвольным списком при проверке: разрешены только два перечисленных generated файла.

Без `--sha256` и без source режима результат означает самосогласованность, а не аутентичность архива. Атакующий может переписать bytes и собственные checksum: доверенный внешний SHA либо сравнение с выбранным источником нужны для идентичности. Полный SHA архива хранится снаружи — в sidecar/итоговой квитанции, а не внутри файла, входящего в этот же ZIP.

На извлечённой копии до `npm ci` можно выполнить:

```sh
node scripts/verify-package.mjs
npm ci
npm run check
```

`verify:package` проверяет публичную проекцию дерева: operational/local-only файлы исключаются и не выдаются за payload. Точная полнота самого ZIP проверяется `verify:release`, который видит каждый член. Для повторной сборки используйте то же имя кандидата в другой выходной папке; при одинаковом источнике SHA должен совпасть.

## Git-коммит, тег и отправляемая история

После осознанной фиксации подготовленных изменений в Git:

```sh
npm run package:source -- --ref YOUR_COMMIT_OR_TAG --candidate rc-check --out outputs/packages/commit-a
npm run verify:release -- --archive /path/commit-a.zip --ref YOUR_COMMIT_OR_TAG --sha256 HASH
npm run check:publication -- --ref YOUR_BRANCH --base YOUR_REMOTE_BASE
```

Значения выбирает maintainer; команды не создают коммит/тег и не пушат. `--ref` разрешается в точный commit, а `--working-tree` не делает такого утверждения и записывает `commitIdentityClaim:false`. Эти режимы нельзя смешивать. Если старый тег ещё не содержит `release/payload-policy.json`, новый маршрут не реконструирует его задним числом; исторический архив сохраняется.

History gate проверяет каждое новое дерево в `base..ref` и итоговый tip. Credential/private/path проверки применяются ко всей новой истории по политике tip и объединению объявленных private входов; полноценные checksum/provenance и обязательный состав требуются у tip. Промежуточный implementation commit не обязан уже содержать финальный release manifest. Поэтому credential, удалённый из последнего дерева, но оставшийся в новом коммите, всё равно остановит проверку. `base` должен быть предком `ref`. Без `--base` проверяется только tip, что явно указано в результате. После новых коммитов или изменения candidate проверка выполняется снова. Штатная защита GitHub остаётся включена; этот инструмент её не обходит и не имитирует удалённый серверный verdict.

## Адресная очистка импортированного provenance

Для известного Mapbox-паттерна внутри cached source HTML:

```sh
npm run provenance:redact -- --path assets/sfx/story/sources/example.html --write
```

Разрешены только существующие UTF-8 HTML в `assets/sfx/{chair,story,courier}/sources/`. Матч заменяется явным marker; оригиналы всех заменённых файлов сначала сохраняются под исключённым `qa/provenance-backups/<old-sha>/`. Ни исходный credential, ни его snippet не попадают в лог. Credit/лицензионный текст и медиа не переписываются. Адресно обновляются hash поля тех текущих metadata, которые ссылаются на эту страницу, запись трансформации и derived manifests. Без `--write` очистка не выполняется. В замороженном пакете с `PACKAGE_SOURCE.json` команда отказывает: импорт выполняется в maintained source.

Общий scan распознаёт только названные семейства: Mapbox access-token, GitHub token, OpenAI-style key, AWS access-key ID и PEM private-key marker. Он не ищет произвольные пароли, не проверяет работоспособность найденных ключей и не является полным security audit. При находке пакер/публикационный gate отказывают; автоматическая redaction ограничена указанным cached Mapbox HTML, остальные случаи требуют адресного исправления источника.

Проверка provenance поддерживает текущие SFX source/page/license/runtime asset связи (описаны в компоненте и тестах); исторические generator/baseline/QA SHA не приравниваются к текущему файлу и не переписываются. Новый metadata формат требует собственного явного binding. Совпадение SHA не означает юридическое разрешение: notices и условия новых материалов проверяет maintainer.

## Формат и границы

Архиватор написан на встроенных средствах Node и создаёт ограниченный classic ZIP STORE: UTF-8, фиксированные дата/права0644, сортированный список, один корневой каталог, до 512MiB и менее65535 файлов. Это осознанно простой воспроизводимый профиль; записи MP4/MP3 уже сжаты, а дополнительных zip/runtime зависимостей нет. Проверка не обещает поддержку произвольных ZIP, Zip64, шифрования, symlinks или других методов. Описание формата — [PKWARE APPNOTE](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT); текст стандарта не включён в поставку.

Имена проверяются на traversal, backslash/drive, control characters, некорректный UTF-8, дубли и case-collision между членами. Приватный путь сравнивается точно; реальный filesystem alias учитывается при чтении working source без потери distinct файлов на case-sensitive FS. Существующая политика static build сохраняется.

Для новой стабильной поставки используйте `--ref` фактического tag/merge commit и `--base` актуального опубликованного main перед отправкой новой истории. Если merge создаёт новый OID, сначала докажите равенство source tree, затем пересоберите финальный ZIP/receipt под правильный commit. Старые гейты переносятся только по явной идентичности.
