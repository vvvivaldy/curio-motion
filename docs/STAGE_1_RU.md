## Изменение поведения

Раньше `fps = Number.MIN_VALUE`, `durationInFrames = 2` проходили positive-finite проверку и могли передать `Infinity` в `pose` на кадре 1. Теперь `validateTimeline` отклоняет timeline с непредставимым последним временем через `RangeError`, до вызова `pose`. Однокадровый timeline с тем же fps остаётся допустим; малый fps с конечным временем также проверен. Обычные корректные сцены не меняют формулу времени или рисунок.

Нового rig, языка сцен, слоя импорта или npm-пакета не добавлено. Новый marker consumer — техническая проба API, не художественный фильм. Новые рисунки, персонажи и звук этого этапа не требовались.

## Проверки

Текущие запускаемые проверки: `npm run check:api`, `npm run check`, `npm run check:api:browser`, полный `npm run check:port`, официальный `npm run render` существующего PinkMonkey с отдельным output. QA сохранена локально в `qa/stage1/`, `qa/public-api/`, `qa/port-check.json`, `qa/remotion-render.json`; переносимая [итоговая квитанция](STAGE_1_VERIFICATION.json) содержит версии, результаты и привязку исходников/проверенных файлов.

Браузерная проба проверяет реальные меняющиеся пиксели Direct Pixi и Player, обратную/произвольную перемотку, отсутствие начального pose при create, копию настроек, неверные кадры, передачу исключений, очистку canvas/children и createDrawing failure, play/pause/unmount. Получено 0 page/runtime console/HTTP ошибок и 0 image requests в API-пробе. Два известных development ref warnings закреплённых React/Remotion записаны отдельно. Предупреждения Node 26 о module.register и Vite о размере bundle также не скрыты. Проба не выдаётся за просмотр/прослушивание художественного фильма.

Полный официальный PinkMonkey: H.264, 1280×720, 24fps, 288 кадров; SHA совпал с принятым `docs/assets/demo-v5.mp4` (`be1d1e05…`). Рассмотрены декодированные кадры 0/204/287 и screenshot API-потребителя. Новый непрерывный просмотр/прослушивание не заявляется; идентичный фильм сохраняет прежнюю приёмку. Исправление time, тесты и контракты проверены прежним независимым критиком, границы поддержки/совместимость — прежним воркером. Обязательных открытых замечаний этапа нет.
