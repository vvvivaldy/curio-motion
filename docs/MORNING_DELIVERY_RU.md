# «Утренний маршрут»: законченная рабочая задача

Пилот этапа 2 до 1.0: 36 секунд, 1280×720,24fps. Живая композиция объединяет векторные титры, принятый эпизод енота, записанные эффекты и учебную сводку. Принятый MP4 включён как `docs/assets/morning-delivery-accepted-v1.mp4`; повторный экспорт создаёт `outputs/morning-delivery-remotion.mp4`; фильм принят владельцем 1 ноября 2026. Принятый фильм включён в локальный состав следующей поставки и витрину; публичная публикация остаётся отдельным решением.

## Запустить и редактировать

Из корня проекта:

```sh
npm run check
npm run dev
# В браузере: /player.html?example=morning-delivery
# Существующий Chrome/Chromium; при необходимости задайте CHROME_PATH:
COMPOSITION_ID=MorningDelivery RENDER_AUDIO_CODEC=aac npm run render
```

Vite печатает фактический локальный адрес. Инструкции среды/PowerShell — в [DEVELOPMENT](DEVELOPMENT.md). Композиция зарегистрирована как `MorningDelivery`; все кадры официального MP4 и Player рисуются из одного scene contract, видеоподложки нет.

| Изменить | Где |
| --- | --- |
| Длительность и планы | `src/examples/morning-delivery/settings.ts`, `motion.ts`; check обнаруживает разрывы/неверные локальные кадры |
| Титры, конверт, цвета, слои | `src/examples/morning-delivery/scene.ts` |
| Историю енота | Исходники `src/examples/raccoon-courier/`; это общий переиспользованный эпизод |
| Числа графика | `src/examples/delivery-infographic/data.ts`; источник общий для самостоятельного графика и пилота. Итог нового титра тоже вычисляется из этих данных |
| События звука | `src/examples/morning-delivery/sound.tsx`; источники и условия — [существующий каталог/credits](../assets/sfx/courier/CREDITS.md) |

Все данные 12/18/30 и итог60 в текущем фильме учебные. При изменении данных прежний фильм/его приёмка не становятся подтверждением нового. В отдельной копии проверен вариант24/16/8 с итогом48: пользовательское редактирование не ломает общий regression check из-за фиксации исходных чисел.

Использованы стабильные сценовые контракты и общий bridge. Внутренние экспорты дочерних примеров переиспользуются осознанно и не добавлены в stable API. Рисунок/анатомия/времена всех672 дочерних кадров не менялись. У нового автора остаются явные шаги scaffold→рисунок/данные→registry→проверки; отдельная продакшен-система агентов не требуется.

## Звук и Player

В текущем монтаже36 событий на8 существующих записанных WAV. Все30 исходных событий енота сдвинуты ровно на72 кадра. Один бумажный фоли относится к появлению конверта во вступлении; ещё5 контактов продолжают тот же фактический exit-run за прежним station cutoff1370 с уменьшением громкости. Это авторское затухание по расстоянию, а не новый физический аудиодвижок.

Пять контактов за прежним cutoff не означают пять шагов после полного исчезновения тела: whole actor pixel заканчивается наglobal417, пусто с418; только последние2 новых cue начинаются после418. Реальный закодированный сигнал и полный хвост продолжаются после исчезновения. Техническая проверка не оценивает на слух материал/естественность.

При обратной перемотке412→379 Player временно монтировал3 старых+3 новых аудиособытия при лимите5. В общем `src/player.tsx` установлен штатный Remotion `numberOfSharedAudioTags={8}`, покрывающий наблюдённые6 и небольшой запас. Для собственной более плотной звуковой сцены проверьте её одновременные события/перемотку и явно настройте этот ресурс Player; число файлов в каталоге не определяет размер этого пула. Экспорт и рисунок эта настройка не меняет.
