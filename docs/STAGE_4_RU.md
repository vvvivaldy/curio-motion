# Этап 4: итоговая проверка кандидата

Проверяется локальный кандидат `stage4-macos`, версия `0.2.0-beta.1`. Это не публичный RC и не разрешение публикации. Точный commit, ZIP/SHA и результаты фиксируются **внешним** отчётом после заморозки: `evidence/stage4/FINAL_VERIFICATION.json`. Документ внутри кандидата не содержит собственного итогового хеша и не выдаёт запланированные проверки за выполненные.

## Шесть обязательных задач

1. **Среда:** официальные Node 22.12.0 / npm 10.9.0 и Node 26.13.0 LTS / npm 11.20.0; SHA дистрибутивов, macOS arm64 и существующий Chrome. Минимум engines остаётся прежним. Для обычной работы рекомендуется актуальный патч LTS; старый минимум проверяется как обещание совместимости.
2. **Чистые Git и ZIP:** локальный кандидатный commit и независимый clone, ZIP из того же commit, четыре отдельные установки (Git/ZIP × два Node), собственные node_modules и npm ci, полный check. По прямому решению владельца официальный объём этого этапа — macOS arm64. Linux/Windows **не проверены**, не имеют PASS и не являются обязательным gate; Docker/новые виртуальные диски не разворачиваются. Запуск GitHub Actions этим документом не подтверждается.
3. **Регрессия и API:** весь настроенный check:port, дополнительно MorningDelivery, stable API, случайная/обратная перемотка, create/draw/destroy, objects и starter; точные количества, ноль runtime/image ошибок.
4. **Player и медиа:** play/pause/seek/replay, полный новый MorningDelivery, беззвучный путь, инфографика; fps/размеры/длительность и декодирование. Прежняя художественная/звуковая приёмка переносится только при доказанной неизменности соответствующих входов/результата. Документационная смена поддерживаемых ОС не требует повторного рендера при том же image-export-v2 snapshot; перенос каждого результата записывается явно, а точный финальный ZIP проверяется отдельно.
5. **Ресурсы и ошибки:** измеренный характерный экспорт, повторное открытие Player; закрытие stage/browser/server при нормальном выходе и ошибках, понятные неверные входы. Нет обещания скорости на любых машинах.
6. **Независимый маршрут и сводка:** другой готовый испытатель использует только поставленные инструкции, меняет рисунок персонажа и данные инфографики, просматривает живой результат и экспортирует полные MP4. Фиксируются препятствия и пределы просмотра/слуха. Независимый критик сверяет финальный кандидат, права/checksum/provenance и отсутствие обязательных открытых пунктов.

Изменения после заморозки отменяют затронутые результаты; исправление сначала получает новый кандидат. Исторический архив этапа 3 сохраняется. Изменения рисунка и звука в этом этапе нужны только для независимой пользовательской пробы, не заменяют принятые примеры.

Следующий этап 5 — подготовка RC и отдельное решение владельца о публикации 1.0. Публичные push/tag/release в этап 4 не входят.
