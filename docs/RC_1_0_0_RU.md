# Curio Motion 1.0.0-rc.1

**Локальный кандидат в релиз; стабильная 1.0 ещё не опубликована.** Тег `v1.0.0-rc.1` — предлагаемое имя, не утверждение о созданном теге или GitHub release. Последняя публичная версия — [0.2.0-beta.1](https://github.com/vvvivaldy/curio-motion/releases/tag/v0.2.0-beta.1).

## Что входит

Редактируемый TypeScript source-project, Pixi/Remotion, 20 названных stable API имён, включённые персонажные примеры/стили, recorded SFX, учебная инфографика, blank scaffold, инструкции пользователю/автору/критику и повторяемая поставка. `private: true` сохраняется: это не npm-пакет, автоматический image-to-animation сервис или универсальная анатомия для любых пропорций.

Официально проверяемая среда — **macOS arm64**, контрольная система macOS 26.6.2 и Chrome for Testing 156.0.8078.4. Совместимый минимум — Node 22.12.0 / npm 10.9.0; рекомендуемая контрольная версия — Node 26.13.0 LTS / npm 11.20.0. Linux/Windows, другие браузеры и архитектуры не объявлены проверенными. Docker для этой поставки не требуется.

## Начать работу

Распакуйте переданный RC ZIP в отдельную папку, сверьте SHA256 из внешнего отчёта. До своих правок выполните `node scripts/verify-package.mjs`, затем:

```sh
npm ci
npm run check
npm run dev
```

Откройте напечатанный адрес и `/player.html?example=morning-delivery` либо `raccoon-courier`/`delivery-infographic`. Для звука нажмите play. Для экспорта укажите executable существующего Chrome:

```sh
export CHROME_PATH="/path/to/installed/chrome"
COMPOSITION_ID=MorningDelivery RENDER_AUDIO_CODEC=aac npm run render
```

[Установка и диагностика](DEVELOPMENT.md) · [Работа с агентами](USAGE_RU.md) · [Переход с 0.2](COMPATIBILITY_RU.md). Для небольшой сцены достаточно автора и владельца; сложным взаимодействиям помогает независимый критик, математик подключается к конкретной геометрической проблеме. Готовая команда агентов не является обязательной зависимостью библиотеки.

## Доказательства и границы

[Baseline этапа 4](RC_1_0_0_BASELINE.json) фиксирует закрытые проверки точного предыдущего кандидата. Относительно него у RC меняются версия корневого проекта/lockfile и документы. Код `src`, скрипты, зависимости, звук и фильмы сохраняются. Полные render-source fingerprints всё равно различаются из-за версии: старые receipts остаются историческими, а перенос гейтов требует отдельного доказательства всех неизменных входов.

Внешние `RC_VERIFICATION_RU.md` и `STAGE_5_FINAL_VERIFICATION.json`, передаваемые рядом с ZIP, содержат **точный commit/SHA этого RC, реально повторённые команды, нормализованную привязку прежних проверок и независимый verdict**. Этот внутренний документ заморожен до окончательного архива и сам по себе не отмечает будущие проверки PASS. Совпадение двух сборок, всех checksum, provenance и исходящей Git history проверяется по фактическим байтам; отчёт не содержит рекурсивного требования включить собственный ZIP SHA внутрь ZIP.

Предыдущий принятый фильм MorningDelivery сохраняется byte exact. Переиспользование его художественной/звуковой приёмки требует доказанной идентичности; автоматический Player/ffmpeg PASS не выдаётся за человеческий непрерывный просмотр или прослушивание. Быстрые reopen вкладок Chrome временно повышают RSS; на измеренной среде наблюдались восстановление после паузы и полное закрытие процессов. Это не гарантия универсальной скорости или отсутствия любой утечки.

## Права

Оригинальный код — MIT. Remotion имеет отдельную лицензию, artwork и записанные звуки — собственное происхождение/условия. [THIRD_PARTY_NOTICES](../THIRD_PARTY_NOTICES.md), [ASSETS](../ASSETS.md) и per-material credits сохраняются. Новых медиа или dependencies в этом RC не добавляется. Цельные `local-only` пользовательские входы исключаются независимо от Git ignore; исходящие Git-коммиты проверяются до публикации.

## Приёмка и публикация

Шесть задач подготовки: статус/версия → changelog/переход → совместимость/права → Git/ZIP/manifest → чистая проверка → независимая сверка и передача владельцу. Техническая подготовка может быть полностью выполнена, пока **владельческая приёмка конкретного RC остаётся PENDING**. Только она закрывает соответствующий пункт согласованного этапа 5.

Владелец получает архив и отчёт, принимает этот кандидат и отдельно решает о публикации. Текущая задача не отправляет push, не создаёт remote release или tag и не считает start-stage инструкцию приёмкой ещё не существовавшего RC. Продвижение к версии 1.0.0 потребует обновить version/manifest/архив, проверить изменённые входы и проверить скачанный публичный результат после отдельно разрешённой публикации. Искусственный период ожидания, квота функций или ещё один творческий фильм не требуются.
