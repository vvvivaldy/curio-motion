## Что изменилось по существу

- Больше не нужен внешний рабочий `package_beta.py`: упаковка и проверка живут в репозитории и работают на Node без установленных npm-зависимостей.
- Общий MANIFEST не скрывает устаревшие вложенные суммы. Packer не переписывает их молча; адресная source-page очистка обновляет только связанные поля и derived checksum.
- Публичный состав не зависит только от Git ignore. Приватный whole input исключён из реальной static сборки и source ZIP. Символьная ссылка в предке `.agents/...` также отвергается до чтения внешних bytes.
- Исправлен обнаруженный критиком case-fold omission: distinct public файл на case-sensitive FS не теряется. Output alias проверяется до создания каталогов, backup alias — до записи. Reader принимает обещанные regular0644, а не0777.
- Known-pattern scan не печатает найденные credentials и не обещает обнаружение любого секрета. Сохранённые notices и медиа имеют отдельные условия; Remotion не назван MIT.
- Working tree, Git tip и outgoing history имеют разные явные режимы. Только root MANIFEST и PACKAGE_SOURCE генерируются при упаковке; других неоговорённых исключений нет.

## Доказательства и ограничения

Финальный архив и его `.sha256`/`.receipt.json` хранятся в `outputs/packages/final-a/`; независимые проверки и итоговая квитанция — в рабочем evidence вне публикуемого source. Тот же candidate из `final-b` должен иметь одинаковые bytes. Получатель проверяет внешний SHA и, при наличии исходного checkout/ref, выполняет source comparison.

Проба до финальных доработок имела665 файлов и собственную независимую чистую установку. Она не выдана за окончательный архив: после неё уточнены history gate, required file list и документация, а финальный кандидат перепроверяется отдельно.

Новый официальный экспорт после включения фильма в витрину и изменения package scripts байтово совпал с принятым фильмом. Защищённые геометрия/движение/звуки и старые фильмы сохранены. Явный src delta к этапу2 — metadata.ts (видимость и путь принятого фильма); это не изменение рисунка.

Это завершение этапа3, а не релиз1.0. Публичная бета/старые архивы не перезаписаны, push/tag/release не выполняются. Следующий этап4 — замороженный кандидат, точные Node-версии, полная RC-матрица и независимый пользовательский вход. Решение о публикации остаётся этапом5.
