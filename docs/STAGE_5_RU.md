# Этап 5: RC и передача владельцу

Версия подготовки — `1.0.0-rc.1`. Шесть технических задач перечислены ниже; их фактическое завершение, точный commit/ZIP SHA и независимые verdict фиксируются во внешних `RC_VERIFICATION_RU.md` и `STAGE_5_FINAL_VERIFICATION.json`, передаваемых рядом с архивом. Этот документ заморожен до этих gates и не выдаёт их план за PASS.

| Задача | Проверяемый результат |
| --- | --- |
| 1. Статус/версия | package/lock/metadata согласованы, RC не объявлен опубликованным |
| 2. Changelog/переход | Понятны изменения с 0.2 и сохранение собственных сцен/фильмов |
| 3. Совместимость/права | 20 stable имён сохранены; поддержка macOS arm64; notices/assets и dependency graph сверены |
| 4. Git/ZIP | Настоящая ancestry от опубликованного main, исходящая история, повторяемый архив, все checksum/provenance |
| 5. Чистая проверка | Два последовательных маршрута Git/minimum и ZIP/LTS с одним активным install-каталогом, собственными npm ci/check и полным официальным RC-экспортом |
| 6. Независимая сверка | Другой готовый критик проверил точный commit/SHA и пакет доказательств; владелец получает готовый предмет приёмки |

**Техническая подготовка 6/6 не означает владельческую приёмку RC.** В согласованном плане пакет 5 включает «независимую сверку и владельческую приёмку». Статус общего этапа остаётся `AWAITING_OWNER_ACCEPTANCE`, пока владелец не примет именно этот кандидат. Решение о публикации RC/1.0 — также отдельное; публикация, remote tag и push в текущую задачу не входят.

Пакеты 1–4 закрыты; [baseline](RC_1_0_0_BASELINE.json) содержит идентичность прежних доказательств. Код и медиа не переписываются ради номера версии. При version/docs-only изменении допускается доказанный перенос прежних гейтов; новый image-export-v2 fingerprint и реально выполненные RC-команды фиксируются честно.
