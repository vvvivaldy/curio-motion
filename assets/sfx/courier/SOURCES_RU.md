# Дополнение записанных звуков: енот-почтальон

Отдельный переносимый пакет: **16 рабочих WAV из 13 разных записей, 12 авторских аккаунтов, 5 групп**. В каждом случае первичная страница Freesound заявляет **CC0-1.0**. Существующие файлы библиотеки и сцена не изменялись. Публикация не выполнялась.

`assets/` содержит моно PCM16 WAV 48 кГц. Все скачанные исходники — официальные публичные **HQ MP3-превью**, а не исходные lossless WAV-мастера. Перевод в WAV не восстанавливает утраченную информацию. Нет нового AI, синтеза, pitch shift, растяжения времени, шумоподавления, наложения нескольких записей или искусственных вариантов одного удара.

## Что именно обработано

`prepare_package.py` декодирует неизменённый MP3 через FFmpeg в float32 48 кГц с сохранением каналов, затем явно усредняет стерео `(L+R)/2`. Выделяет точный диапазон сэмплов, применяет записанный линейный gain и короткие косинусные fades по краям, округляет `x*32767` в PCM16. Для двух вариантов одного обувного источника gain одинаковый; различие уровня/формы относится к разным записанным контактам. Диапазоны времени относятся к декодированной MP3-шкале.

В `manifest.json` для каждой записи есть группа/вариант, материал/роль, URL, автор, лицензия, исходный/выходной SHA256, границы времени/сэмплов, gain/fades, длительность, формат, пики, RMS, размер, техническая точка активности, версии/хэши подготовки. `technicalActivityAnchorSeconds` — начало 5 мс RMS-блока, достигшего 20% максимума; это не услышанная атака.

## Подборка и техническая проверка

Открыть `audition.wav` или компактный `audition.mp3`; [порядок и время каждого файла](AUDITION_RU.md). Подборка содержит точные готовые PCM-срезы без дополнительного усиления/наложения: 0,65 с между файлами, 1,25 с между группами, 0,75 с в начале/конце. Речи и музыки нет. У MP3 возможна задержка кодека; точные времена даны для WAV.

`analysis/verification.json` — результат проверки `verify_package.py`: контроль SHA/лицензий/формата, повторное декодирование каждого исходника и побайтовое восстановление PCM по manifest, непустой рабочий уровень, отсутствие full-scale PCM-сэмплов, запас пиков после 4× ресэмплинга, уникальные SHA и проверка корреляции для обнаружения простых копий. SHA новых исходников и WAV также сравниваются с сохранённым исходным baseline библиотеки. Внутренние короткие паузы и естественные тихие хвосты отдельного удара разрешены; целиком тихих файлов нет.

### Повторная проверка после переноса

Сохранить весь пакет с его структурой, включая `analysis/library-inventory.json`, и запустить `python3 verify_package.py` из Python с NumPy; нужны имеющиеся FFmpeg/FFprobe по указанным в скрипте путям. Проверка не вызывает `prepare_package.py` или полный `analyze_sources.py`, не меняет аудиобайты и не создаёт PCM/NumPy-массивы на диске.

Проверка дублей использует только `audioBaseline.files` из локального `analysis/library-inventory.json`: 89 SHA256 аудиофайлов исходной библиотеки **до добавления courier**. SHA самого baseline закреплён в `manifest.json.verificationBaseline`. Исторический `readOnlyLibraryRoot` внутри inventory — только происхождение снимка; скрипт не открывает эту папку и не зависит от её существования. Живой установленный каталог не сканируется: установленная копия собственного WAV не считается старым дублем. Поле отчёта `duplicateComparison.mode` явно равно `saved-original-library-baseline`, а `liveInstalledCatalogScanned` — `false`.

Контроль SHA собственных `assets/`, восстановление PCM из локальных `originals/` и проверка подборки выполняются отдельно и не отключаются сравнением с baseline. После запуска обновляется только `analysis/verification.json`. `analysis/portability-check.json` фиксирует испытание из отдельной копии с имитацией установленных public WAV и блокировкой обращений к исходной библиотеке. `SHA256SUMS.txt` содержит относительные пути всех остальных файлов пакета; если содержимое сохранённого отчёта изменилось, checksum нужно пересчитать перед следующей передачей.

**Слуховое восприятие в текущем режиме недоступно. Агент не утверждает, что прослушал или художественно принял звук.** Фон, характер и пригодность выбранного среза требуют прослушивания владельцем. Техническая проверка не подтверждает естественность, финальный баланс или синхронизацию фильма. Общие проверки проекта и экспорт здесь не запускались: проект не изменялся, проверялись только новые аудиофайлы и происхождение.

## Предлагаемое применение в 16-секундной сцене

Диапазоны прочитаны из текущего авторского `motion.ts`; после правок анатомии автор должен привязаться к окончательному видимому контакту, а не слепо копировать время.

| Действие / текущий диапазон | Кандидат | Как применить |
| --- | --- | --- |
| Подбегание 0,2–3,45 с и уход 12,1–14,75 с | `shoe-wood-leather-01/02`; альтернативные банки `shoe-wood-sneaker-*`, `shoe-wood-vans-*` | Сначала выбрать один подходящий банк на слух; чередовать его реальные контакты на опорах `runPlans.contacts`. Вычитать техническую activity anchor только как исходную подсказку. Не накладывать весь walking loop и не менять обувной материал на каждом шаге |
| Лапа касается стойки около 4,1 с | `wood-desk-touch` или `wood-table-touch` | Один тихий отдельный контакт. Это замена текущего повторно используемого wood-drop в данной сцене; старый файл не удалять. Сверить контакт после правки руки |
| Захват около 4,4–4,65 с, начало подъёма 4,65–5,35 с | `paper-pickup-note`, при необходимости `envelope-desk-slide` | Короткое взятие; скольжение — только если конверт реально скользит по столу. Не озвучивать одно действие сразу всеми кандидатами |
| Разворот конверта 6,55–7,25 с | `paper-turn-book` | Один шелест внутри видимого поворота; это страница как фоли. Проверить, не звучит ли слишком крупным книжным жестом |
| Перенос к сумке 8,15–9,15 с | `paper-finger-pass` либо `bag-leather-flex` / `bag-cotton-rustle` | Бумага — при изменении хвата; кожа или хлопок — при реальном сгибе сумки. Кожаная и хлопковая версии — альтернативы, не обязательные слои |
| Вкладывание 9,35–10,3 с | `paper-finger-pass` или `paper-soft-brush` | Привязать движение бумаги к входу в сумку; готовые длительности сохранять, не растягивать всю запись до диапазона |
| Успокоение сумки/бумаги 10,5–10,8 с | `bag-cloth-shift`, при необходимости | Одна негромкая деталь при видимом остаточном сдвиге; не создавать непрерывный шум в неподвижной паузе |

## Интеграция после согласования

1. Скопировать только 16 `assets/*.wav` в `public/audio/sfx/courier/` целевого проекта. Старые файлы не заменять.
2. Сохранить весь пакет происхождения в `assets/sfx/courier/`: manifest, credits, sources, originals и скрипты. Большие промежуточные NumPy-массивы не входят в готовый пакет.
3. `catalog-entries.json` содержит 16 элементов в форме существующего `catalog.json.entries`, с путями происхождения, уже приведёнными к `assets/sfx/courier/`. Добавить эти элементы в существующий массив после проверки отсутствия ID, не перезаписывать весь старый каталог. `manifest.json` остаётся переносимым каталогом со своими относительными packageFile.
4. Использовать прежние Remotion `Sequence` / `Html5Audio` / `staticFilePath`; не запускать звук из pose/draw/ticker. Новый движок не нужен.
5. После выбора и настройки громкостей — проверка окончательных видимых контактов, хвостов, Player play/seek/mute, настоящего AAC и полного MP4. Эта работа ещё не выполнена в данном пакете.
